Two layers: brand and action

A yellow, red or green brand cannot colour the buttons: yellow is the till's warning colour, red is void, green is paid. So the brand never goes on anything a cashier presses or reads as a status. It goes where it identifies the business, and there any colour works, as long as it can be seen.

Brand colour — the business's own

  • Lock screen: divider, PIN dots, Enter button
  • A ring around the logo
  • The sidebar tint and a thin brand strip across the top
  • Rule: visible on the till's dark screens (3:1). No status rule, because it never marks an action or a status
  • Already stored today: it is the Phase 1 lock-screen colour

Action colour — one of the curated themes

  • Buttons, including Charge; selected category and item; links and active tabs
  • Rule: every check in the table below, including "never looks like a status"
  • New in Phase 2: the business picks a theme name. The web page suggests one that sits well beside its brand colour

What an action theme is

A theme is one colour family with a fixed shade for each job. The shade for each job was found by testing every family against the till's real surfaces; the same shade number worked for all of them, which keeps authoring and review simple.

A theme changes

  • Primary buttons, including Charge
  • Selected category, selected item, active menu item
  • Links and active tabs
  • The lock screen's divider, PIN dots and Enter
  • An optional tint on the sidebar

A theme never changes

  • Totals, prices, keypad digits, body text
  • Page and card backgrounds, apart from the sidebar tint
  • Green for paid and done, amber for warnings, red for void and errors
  • The receipt, which stays black and white

One change follows from this. Today the till's main action colour is green, the same green that means paid. With themes, green returns to meaning success only, and the theme carries the main action. The unthemed default needs the same treatment; see the decisions below.

How each candidate did

Every number below is computed in this page from the colours themselves, using WCAG contrast and the CIEDE2000 colour difference. A theme ships only if every cell passes. The status test asks for a difference of at least 20 from the paid, warning and void colours, on both the button shade and the text shade, so a themed button can never be mistaken for a status.

Brand colours: any hue that can be seen

The same checks, for colours used as a brand colour. Only visibility on the till's dark screens applies. The status column shows why these may not be action colours, even though they are welcome as brand colours.

Decisions for you

Two layers: the business's own colour for identity, a curated colour for actions

This is what lets a business with a yellow, red or green brand see that colour throughout the app without its buttons looking like warnings, voids or payments. It needs no new data for the brand layer: the colour already saved for the lock screen becomes the brand colour.

Recommendation: adopt it.

Which themes ship first

Theme as a family of shades, not one colour

The Phase 2 scope described a theme as three colours. That cannot work across a dark till and a light dashboard: a colour bright enough for the till fails on white, and one dark enough for white is hard to see on the till. Storing a family (and a fixed shade per job) solves it, and the business still makes a single choice.

Recommendation: adopt the family model. The stored value stays a single theme name.

What the unthemed default looks like

Today's default lock-screen colour is Teal, which qualifies as an action theme only after a till check. A business that has picked nothing should get a safe, plain look.

Recommendation: Ocean as the default action colour; no brand colour until the business sets one (the lock screen then uses Ocean).

How strict the status test is

At 15, Teal and Pink qualify; at 20 they would not. Nothing else moves: Emerald, Rose and Amber sit far closer to paid, void and warning (the table shows Amber and Red are the status colours themselves), so no threshold makes them safe for buttons.

Recommendation: 15 to qualify; any theme between 15 and 20 ships only after a check on a real till under shop lighting. Emerald, Rose, Amber, Red and Yellow remain welcome as brand colours.

How different the themes must be from each other

Offering two themes that look almost the same wastes a slot and confuses the choice. The proposal asks for a difference of at least 10 between any two themes' button colours, which is plainly visible side by side. That rule is what leaves Iris out: it is too close to Violet.

Recommendation: 10. Raising it to 15 would leave three themes.

The Phase 1 colour

With two layers there is nothing to reconcile: the colour a business already chose for its lock screen simply becomes its brand colour, and keeps working exactly as it does today. A business with no brand colour gets its action theme on the lock screen too.

Recommendation: keep today's lock-screen colour as the brand colour; no migration.

Where the business's own receipt line prints

The scope puts the business's footer line under the thank-you. Today it prints above it. Either order keeps the thank-you single, the tax line and the SwiftPOS credit last.

Recommendation: keep today's order; it is already on customers' receipts.

Who gets themes

The scope frames themes as a premium feature. The switch for that already exists: a per-business feature flag, the same kind that turns on web hosting.

Recommendation: ship behind a flag, off by default, and decide the price separately.

What happens after you decide

The approved set becomes a small registry in the code, checked by a test that runs exactly the checks on this page. Then the app gains a theme layer, the branding record gains a theme name and optional per-branch override, and the web Branding page gains a theme picker with a full-screen preview. The last and largest step is walking every screen, every button state and both dashboard modes on a real till for each theme. That walk is why a small, curated set matters.

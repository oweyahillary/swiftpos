Email — the real story

Not a bug, and not your credentials. The SwiftPOS daily-summary emails delivered fine in July, so the SMTP config is correct. On Render's free tier, outbound SMTP (both 587 and 465) is now blocked at the network layer — the boot log shows Both submission ports blocked. No code change reaches a filtered port.

Fix (Render dashboard env, no code):

  1. Create a Resend API key → set RESEND_API_KEY.
  2. Verify a domain at resend.com/domains and set NOTIFY_FROM_EMAIL to an address on it (not a gmail address).
  3. Save & redeploy. Boot log flips from RESEND_API_KEY not set… to [mailer] Resend configured (primary).

Resend sends over HTTPS/443, which the host does not block. Confirm delivery on demand with the new owner-only endpoint POST /api/notifications/test-email → { ok: true, provider: "resend" }. Register A54 stays open until the key is set.

Gotchas worth knowing

  • CI is the real gate, not local. It caught three regressions local Node 20 could not (schema-version pairing, a node:sqlite lane crash, and a main-build dependency). Wait for a green CI run before building the .exe.
  • node:sqlite tests need Node 22. On Node 20 they skip (or error if run raw); CI runs them on a dedicated Node-22 lane. A few tests also need apps/server built first (they import from dist).
  • Commit narrowly. Prefer git add <path> over git add -A when applying a delivered file, so nothing stale rides along.

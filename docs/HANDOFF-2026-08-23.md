## 5. FAILED ATTEMPTS / TRAPS / LESSONS

1. **The production incident itself (A152) — the "test that failed."** With the
   Render cloud API down, desktop tills could **not** sign in, though the app is
   meant to keep trading offline. Confirmed root cause: the offline fallback fires
   only on a *thrown* transport error; `ownerFetch` returns the raw response and
   doesn't throw on a 5xx, so a "down-but-responding" cloud (502/503 from the
   platform edge) is treated as a *rejection*, not *unreachable* → node/cache
   fallback never reached. **This is the #1 morning task (§6).**
2. **The A143–A148 static "endpoints live, UI unwired" sweep was unreliable** — its
   matcher missed `?query` suffixes and wrapper call sites. Of the items it flagged:
   A147 (2 of 3 already wired), A145 (redundant + a security hole), A8 (a fully dead
   triad), A130 (a dead report), A148 (a minor asymmetry, not redundant) were
   false-positives / redundant / dead. **Lesson, adopted for the rest of the
   session: verify each item at source, one at a time, before building.**
3. **A17 register drift.** A17 was tracked as an "unstarted design gap — do not
   patch," but PHASE5 §4 had in fact been **built** (node verify-pin, `branch_staff`
   roster, the peer authority chain, non-expiring cache). The source pass (-s)
   corrected the record. Lesson: re-read source before trusting a stale entry.
4. **Patch entanglement (-o/-p).** Even-split (-o) and the by-item/cleanup batch
   (-p) both edited `PaymentModal`/`CashierScreen`; -o hadn't been committed, so the
   two were mixed in the working tree. Resolved by resetting to the -n baseline,
   re-applying the delivered -o patch, committing it, then re-laying -p. **Lesson:
   commit each delivered patch as a baseline before starting the next batch.**

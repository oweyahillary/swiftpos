# MANIFEST 2026-09-10-D3 — auto-update wired (D3 OPEN → FIX BUILT)

**Base:** `origin/dev`. **Desktop main + build config + CI + a test + register.** No migration,
no server change, no dashboard change.

## What this does
Turns the dormant `autoUpdate.ts` scaffold into a working auto-update pipeline. Installed PROD
tills will, once the first release is cut, check GitHub Releases on launch + every 6h, download a
newer version in the background, and install it on next quit — never mid-service. This is the end
of A1 (no more hand-built `pos.zip` per till).

## The pieces
1. **Dependency:** `electron-updater@^6.6.2` added to `apps/desktop` (pairs with electron-builder 26.x).
2. **Build inclusion:** removed the `autoUpdate.ts` exclude from `tsconfig.main.json` — it now
   type-checks and builds (0 errors).
3. **Wiring:** `index.ts` imports and calls `initAutoUpdate()` after `createWindow()`, guarded in a
   try/catch so a failed init never stops a till trading.
4. **Runtime safety:** `autoUpdate.ts` skips dev in two ways — `!app.isPackaged` (dev run) AND the
   "SwiftPOS Dev" flavour by name — so a dev till never pulls a prod release.
5. **Publish target:** `electron-builder.config.js` — PROD publishes to GitHub Releases
   (`oweyahillary/swiftpos`); DEV publishes `null`. Feed is prod-only.
6. **Release automation:** new `.github/workflows/release.yml` — on a `v*` tag (or manual dispatch),
   builds shared/printing → desktop (prod) → NSIS installer → `--publish always` on Windows, using
   the Actions `GITHUB_TOKEN`. This is the CI piece that closes A1.
7. **Guard:** `tests/autoupdate-wiring.test.mjs` (12 checks) asserts every piece above; mutation-checked.

## Unsigned — deliberate, for now
Runs without a code-signing cert. The update mechanism works; Windows SmartScreen shows on first
install ("unknown publisher") until a cert is added. To sign later: add repo secrets `CSC_LINK`
(base64 .pfx or path) + `CSC_KEY_PASSWORD` — electron-builder picks them up automatically, no
workflow change. For an unattended POS till, a cert matters more than for a normal app (no one to
click "Run anyway"); Azure Trusted Signing (~$10/mo, immediately trusted) is the cheapest path.
See `docs/DESKTOP-AUTOUPDATE.md` §4.

## NOT verified here (rule 16) — the close condition for D3
The end-to-end update loop needs a real Windows till and a published feed, which the Linux bench
can't do:
1. Push a tag, e.g. `git tag v0.5.40 && git push origin v0.5.40` (or `npm version patch` in
   apps/desktop then push the tag). The release workflow builds + publishes the prod installer.
2. Install that published v0.5.40 on a Windows machine (from the GitHub Release, not a local build —
   it must carry the feed metadata).
3. Bump to v0.5.41, push the tag, let the workflow publish.
4. Launch the installed v0.5.40 → within seconds the log shows `update-available` then
   `update-downloaded`; quit → it installs; relaunch → v0.5.41. That loop working closes D3.

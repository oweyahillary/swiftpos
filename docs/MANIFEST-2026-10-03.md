# MANIFEST 2026-10-03 — desktop 0.6.34: the business day ends at the owner's cut-off (A382)

**Base:** origin/dev `799bb77`. **Delivered as:** `swiftpos-2026-10-03-v0.6.34.patch` — includes the version bump
(apps/desktop and `shared/release.ts` → 0.6.34). **No migration** (a business setting). Cloud, web and till; local schema 64
(the cloud then requires it).

Found in the lead review (2026-10-03): a hotel bar trading past midnight was locked at 00:00 — "Trading day … was never
closed. A manager must count the cash and close it" — mid-service; with 24-hour operation, at 02:00.

## What changes
- **Settings › Business › Business day ends at** — 00:00 (midnight, the default: nothing changes) to 06:00 in half hours.
  A branch may override it (Branches › the branch › overrides). A bar open until 3 am sets 04:00.
- **The till:** a sale before the cut-off belongs to the night before. The till keeps selling through the night; after the
  cut-off the day must be closed, as before (a manager). With 24-hour operation the 2-hour grace runs from the cut-off.
  History's "Today" shows the whole night.
- **The cloud:** every dashboard report and the daily email count the business day (cut-off to cut-off).
- **The web POS:** History's "today" follows it (the web POS has no day lock).
- **Not changed:** the dashboard's date pickers default to the calendar date — a report opened between midnight and the
  cut-off shows the new (empty) day; pick yesterday.

`scripts/check-shared-sync.mjs`), `apps/server/src/lib/dayCutoff.ts`, `apps/dashboard/src/lib/webDayCutoff.ts`,
`tests/business-day.test.mjs` (8), `apps/desktop/test/business-day.test.mjs` (14; CI step). CHANGED: cloud
`routes/business.ts`, `routes/branches.ts`, `routes/pos.ts`, `routes/reports.ts`, `jobs/dailySummary.ts`,
`lib/desktopSchema.ts` (64); till `main/dayService.ts`, `deviceConfig.ts`, `localDb.ts` (64), `syncEngine.ts`,
`referenceBundle.ts`, `managerReports.ts`; web `settings/BusinessProfileTab.tsx`, `settings/BranchReceiptOverrides.tsx`,
`pos/POSOrderHistoryTab.tsx`, `pos/cashier/usePOSData.ts`; version 0.6.34; `.github/workflows/ci.yml`;
`docs/AUDIT-REGISTER.md` (A382), this file.

## Rollout (owner)
1. Apply, commit, push to dev; CI green. Merge to main (cloud and web deploy; no migration). Tag v0.6.34 from dev.
2. Approve 0.6.34 for a test client; T1 updates.

   00:30 the till still sells; History shows the evening's sales; after 04:00 it asks a manager to close the day.
4. Set it back to 00:00 → the till locks at midnight again, as before.

# desktop 0.6.36: the product is ZapTill (A386)

**Base:** origin/dev `001357e` (= main `b1cbb68` content). **Delivered as:** `swiftpos-2026-10-03-v0.6.36-zaptill.patch` —
includes the version bump (apps/desktop and `shared/release.ts` → 0.6.36). **No migration.**

## What changes
- Every name a person sees reads **ZapTill**: till (PIN screen logo, titles, receipts, Z-report, reports, update banner,
  Help), web (sign-in, favicons, receipts, documents), admin portal, the cloud's emails and messages, M-Pesa prompt text,
  the print bridge's banner and test print. New app icon: teal **Z**.
- `zaptill` reserved as a client address; the admin's Sign-in address is suggested from the business name; an unknown
  address offers **Go to ZapTill sign-in**.

## The Windows app
Renamed ZapTill: installer `ZapTill-0.6.36.exe`, Start menu, Apps list, data folder `%APPDATA%\ZapTill`. On first start the
till moves `%APPDATA%\SwiftPOS` there (database, saved sign-in, log, backups) before anything opens it; the app id stays
`com.swiftpos.desktop`, so the update installs over the old app. **Test on T1 first:** after the update the till must
open signed in, with its sales; `%APPDATA%\SwiftPOS` is gone and `%APPDATA%\ZapTill` holds swiftpos.db.

## Kept on purpose
The app id, the database file name, print-server exe/task/service names, the firewall rule, `X-SwiftPOS-*` webhook
headers, the eTIMS registrant id, stored generic till labels, browser storage keys and env names.

## A215 — inventory writes are permission-gated (no manager stock fabrication)
- **PASS if (UI):** nowhere in the manager portal is there an **Adjust / Edit / Deactivate stock**
  control (only Receive-type actions). The reorder **"min"** field on the Inventory page **is** editable
  by the manager and saving it succeeds (this is intended — see note).
1. Manager → **Inventory**. Confirm: no adjust/edit/deactivate; changing a product's **min** and moving
   off the field saves without error.
- **PASS if (optional, API — proves the route gate):** with the **manager** token, a call to
  `POST /api/inventory/adjust` returns **403**; with a **cashier** token, both
  `POST /api/inventory/adjust` and `PATCH /api/inventory/:id/threshold` return **403**.
  - How: DevTools → Network → copy the `Authorization` header from any manager request, then from a
    terminal: `curl -i -X POST <server>/api/inventory/adjust -H "Authorization: Bearer <token>" -H "Content-Type: application/json" -d '{"product_id":"…","branch_id":"…","type":"correction","quantity":1}'` → expect **403**.
  - Skip if you can't easily get a token — the UI check above is the primary one.
- **Note:** the "min" (reorder alert) being manager-editable is **intended** (owner decision) — it's an
  alert threshold, not the stock count, so it can't fabricate stock.

## A221 — transfer receipt books the ACTUAL received quantity
- **PASS if:** when receiving an incoming transfer, you can enter a received quantity **per line**
  (defaulting to the sent amount, capped at it), add a **note**, and confirming books **only what you
  entered** — the destination stock rises by the entered amount (not the sent amount), and the note is
  saved on the transfer.
1. As **owner** (or the *westlands* side): create a transfer *westlands → Main Branch* for e.g. **5 ×**
   a product, mark it **In Transit**. Note Main Branch's current stock of that product (call it `X`).
2. As **Eugene** (Main Branch): Receiving → **Incoming transfers** → **Receive**.
3. Enter a received quantity **less than sent** (e.g. **3**), type a note ("2 short, damaged"), **Confirm
   received**.
4. **PASS if:** that product's stock at Main Branch is now **`X + 3`** (not `X + 5`); the transfer left
   the incoming list; and the note is visible on the transfer record.

## A218 — manager initiates a transfer from their OWN branch
- **PASS if:** the manager can create a transfer **from their own branch** (source shown/locked, not
  chosen) **to another branch**, despatch it, and the other branch can then receive it. The manager
  cannot source a transfer from a branch they don't manage.
1. As **Eugene** (Main Branch): Receiving → **New transfer**.
2. Confirm **From** = *Main Branch* (fixed, your branch), **To** = a picker listing the **other** branch
   (*westlands*) but **not** Main Branch.
3. Add a quantity for one or more products → **Create transfer**. It appears under **Outgoing transfers**
   as *not yet despatched*.
4. Click **Despatch** → status becomes *in transit* and Main Branch stock **drops** by the sent amount.
5. As the **westlands** side (owner or a westlands manager): receive the transfer (A221 flow) → westlands
   stock rises. **PASS if** the whole loop works.

How to know what's actually live: ignore the GitHub "Environments" names — most are auto-created by Vercel/Render. The truth for a running URL is the Vercel dashboard (project → Deployments → the one tagged "Current / Production"; Domains tab shows the URL) and the Render dashboard (service URL + latest deploy). Fill each live value below and tick it once verified.
API · Render

Prod Server (Render)

The Express API the dashboard, admin and tills all talk to.
Verify it's prod & live
  • Open <URL>/health → returns ok / 200.
  • Render dashboard → this service is the non-dev one, latest deploy = Live, on branch main.
Web · Vercel

Prod Dashboard (Vercel)

The manager/owner web app (payment methods, reports, settings).
Verify it's prod & wired right
  • Vercel → the non-development dashboard project → Deployments → deploy tagged Production / Current; Domains tab = this URL.
  • Settings → Environment Variables: the API base points at the Prod Server (not the dev Render). This is the one real cross-wire risk.
  • Load it, open Payment methods, add + delete one → proves it hits prod + migration 86 is live.
Web · Vercel

Prod Admin (Vercel)

The internal admin app (separate Vercel project from the dashboard).
Verify it's prod & wired right
  • Vercel → the non-development admin project → Production deploy; Domains tab = this URL.
  • Env vars: API base = Prod Server, not dev.
Database · Supabase

Prod Database (Supabase)

The prod Postgres. Migrated only by the DB migrate (production) GitHub Action.
Verify it's prod & current
  • This ref is the one inside the DATABASE_URL secret on the plain Production GitHub Environment.
  • Actions → DB migrate (production) → latest run green, Plan shows pending: 0, Verify = PASS.
  • Supabase → this project → Table editor has payment_methods (migration 86).
Desktop · hand-installed

Prod Tills

Electron tills in the field. They do NOT auto-update — they change only when you build & install.
Verify
  • On a till: it points at the Prod Server, not dev.
  • Hold new prod builds off live tills until the A101 offline-auth checklist passes (a bad auth build = a site visit).
The one real cross-wire risk: a prod web app (dashboard or admin) whose API base still points at the dev Render. You deployed them on separate days to avoid this — the two API-base fields above are where you prove it. If both equal the Prod Server URL, you're clean.
Don't rename the – swiftpos-… GitHub environments — Vercel/Render recreate them on the next deploy. Only the plain Production is yours (the migrate workflow). Stale Preview – … entries are safe to delete.

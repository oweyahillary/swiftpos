## What I built (Android 0.4.7) — two features, both verified headless, both need an on-device test

The theme was your ask: **finish printing so you can test a printer** (IP, or USB-on-a-PC). The byte generation and the
IP/branch-server transport already existed — the real gaps were **no way to set up or test a printer in the app**, and **no
way to retry a print that failed because the printer was off**. Both are now done.

### 1. Set up and test a receipt printer (POS → ⋯ More → **Printer settings**)
- New **Receipt printer** field: the network address of a printer on this device's network (e.g. `192.168.1.50`, or
  `192.168.1.50:9100`). This is the address real receipts already print to on a Shop POS — now there's finally a place to
  set it. Leave it blank when receipts print through a connected computer.
- New **Test print** button: prints a small, clearly-marked test receipt **the same way a real receipt prints**, so a pass
  proves the real path, and tells you which path printed:
  - joined to a **branch server** (the PC that holds a **USB/IP printer**) → prints there, on that PC's printer;
  - otherwise → straight to the **IP printer** at the address.
- Clear failure messages: *enter an address · the computer has no printer set up · received but nothing printed — check it's
  on and has paper.*

**Test it:** on the tablet, open Printer settings, enter your IP printer's address, tap **Test print** → a test receipt
should come out, and the line under the button should say where it went. If you run the till joined to a PC, leave the
address blank and Test print should hit the PC's printer.

### 2. Retry a failed print in one tap
- When a print fails because the printer was **off**, the on-screen print notice now shows **Retry** — switch the printer on,
  tap once, no need to re-ring the sale or find it in History.
- A bad **address** is a setup mistake, not a retryable failure, so it does **not** offer Retry (fix the address instead).
- The sale is always saved before anything prints, so nothing was ever at risk — this just makes recovery one tap.

**Test it:** ring a sale with the printer switched off → the notice appears with **Retry** → switch the printer on → tap
**Retry** → the receipt prints. With a wrong address, Retry should NOT appear.

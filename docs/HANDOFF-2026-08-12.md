## 4. Changes made

**A65 · the daily-report scheduler (NEW, closed).** The problem you reported —
"save send reports shows saved but reverts to off" — was two bugs. (1) The
dashboard reads its toggle from `GET /api/business/settings/report-schedule`,
a route that **did not exist**; the 404 was swallowed by a `.catch(() => {})`, so
the toggle fell back to *off* on every load. The value had saved; it was never
read back. Added the route. (2) The sender ignored the config entirely — fixed
global cron, owner-only, no `enabled`/`recipients`/`send_time`. Rewritten to send
per business only if enabled, at that business's own `send_time` (EAT), once per
EAT day (dedup stamp), to **owner + active branch managers + the added
addresses**, deduped; cron now every 15 min. Your three decisions are recorded in
the entry. **Two behaviour changes to know:** no business has `enabled=true`
persisted yet (the read was broken), so after deploy only opt-ins get mail — the
always-on owner mail stops until each opts in; and if the prod env
`DAILY_SUMMARY_CRON` is set once-a-day it defeats per-business `send_time` — unset
it.

**A54 · mail transport (STAYS OPEN).** Cross-referenced to A65 and left open. A54
is the filtered SMTP port, blocked on the three owner checks in its entry (Render
instance plan, Gmail App Password, the `sync:false` env vars). A correct
scheduler still sends into a filtered port. The live A65 check — enable a test
business with `send_time` a few minutes out — is also the cleanest end-to-end
test of A54's transport.

**A10 · `PrinterSetupScreen` docstring (closed).** It claimed to replace four
components; it replaces one. `PrinterSettingsModal` and `PaperWidthControl` are
still live on the POS screen (re-verified: `POSPage.tsx:21` imports the modal,
which renders the control). Docstring corrected to the truth.

**A11 · `ManagerPage` self-contradiction (closed).** The `printers` nav comment
said `PrintersTab` "stays reachable" **and** "remains … unrouted." It is
unrouted, therefore not reachable. Rewritten to say so.

**A43 · orphaned exclusions (closed, smoke-test pending).** The read-only
kitchen-exclusions box lived only on the unrouted `PrintersTab`. Ported into
`PrinterSetupScreen`, which is mounted by `ManagerPage`'s `case 'printers'`. The
list is cloud-owned and read-only on the till (synced `syncEngine.ts:645`, read
via the live `escpos:kitchenExclusions` IPC), so there is no save path to break.

**D15 · dead `public.sync_queue` (closed).** No reader or writer anywhere; the
live queue of that name is the till's SQLite table, a different schema. Dropped by
migration 80. Removed from `schema-index.json` in the same change.

**`check-schema-drift` · drop-netting (gate fix).** Dropping `sync_queue` tripped
the gate: baseline *creates* it, so the gate expected it in the index. It never
understood `DROP TABLE`. Now it processes migrations in order and subtracts drops,
so a created-then-dropped table is not expected — and create→drop→recreate is
handled too.

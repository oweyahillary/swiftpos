  variants/modifiers → description text → title alone. No menu is forced into one
  shape.
- **`combo_items`, not `component_slots`.** Slots carry customer choice and
  upgrade pricing and need a POS picker. A kitchen ticket needs neither.

## 4. CHANGES MADE

### Money and correctness — 12 register items
`/pay` gained a claim-before-write lock (`.eq('status','open').select()`), closing
duplicate charges, doubled stock and doubled loyalty. Loyalty on `/pay` was
awarding **a tenth** of the counter path; both now share one formula, the ledger
row, `total_spent` and `loyalty_points_used`. Three racy stock writes became
atomic RPCs — one of which, `adjust_product_stock`, had existed since migration 61
and was never called. Fuel stopped being deducted twice. `fetchAllIds` got a
stable ORDER BY. The owner-lockout bug turned out to be in **three** places, not
two, and is now one shared resolver behind a 409 and a business picker.

### Printing — 19 bugs
Detailed in AUDIT-REGISTER §P. The shape of it: the subsystem was complete except
for the wire, and every layer between the cart and the paper had an assumption in
it. Highlights worth carrying forward:

- **`-args` does not bind with `-Command`.** One root cause behind three separate
  "the printer is broken" failures. Values now travel in the environment.
- **The HTML measuring window had no width**, so Electron defaulted it to 800px
  while printing at 302px. Every HTML print was truncated; the shift report lost
  its entire cash reconciliation.
- **The bridge used literal station ids** that never matched real UUIDs, so
  kitchen routing selected nothing while dispatch (which ignores routing) looked
  fine.
- **Production and receipt tickets fired together at payment.** Now split:
  kitchen and dispatch on *send*, receipt on *pay*.

### New capability
Owner-stated kitchen exclusions, per business, cached per till, applied to every
source of units. Plus a dashboard Stations page — stations became data, so a
client adding "Barista" no longer needs a rebuild.

### Infrastructure
Two gates that would have caught two of tonight's P0s, both wired into CI. The
drift gate now actually runs — the job named "Schema drift" had never invoked it.

## 5. FAILED ATTEMPTS — read this one

Recorded because each cost a build, and the pattern matters more than the
individual mistakes.

1. **Diagnosed the printer three times from message text, and was wrong each
   time.** "No printer by that name" (name was correct). "Check power and cable"
   (printer was on). Both because the classifier pattern-matched on prose —
   `GetPrintQueue` was in the "not found" regex, so any exception *inside* that
   call reported a bad printer name. **A confident wrong message is worse than
   none.** Failures are now classified on Win32 codes only, and say "this is a
   fault in SwiftPOS" when they are.

2. **Swapped a working API on a false reading.** Concluded `System.Printing` was
   the wrong choice and rewrote it as Win32 P/Invoke. The real fault was that
   `$args` was always empty, so the old API had never been given a printer name.
   The rewrite is better and stays, but it was made for the wrong reason and
   shipped the same bug again.

3. **Fixed one half of a pair.** `escpos:preview` and `escpos:test` take the same
   inputs. Fixed the shape mismatch on preview, didn't check test, shipped it
   broken. `check-ipc-parity` proves a channel *exists*, not that its two sides
   agree on the payload — that gap is still open.

4. **Told the user "we can't build the menu composition tonight."** They pushed
   back; they were right. 18 of 19 composite items already had their defaults
   resolved in the draft, and the blocking questions were about *pricing*, not
   composition.

5. **Proposed keyword-guessing for kitchen exclusions** after having already
   generated the data that answered it properly. The user proposed an explicit
   list instead, which is better and is what shipped.

6. **Hardcoded a business name** in the menu import for a client who had not been
   onboarded. The file would have refused to run. Now takes a business id.

**The common thread:** every one was inference presented as fact. Where a check
was possible and skipped, it cost a round trip to hardware.

## 4. Changes made, by bug

### P0 — shipped

**BUG-01/02 — tipped sales refused.** `create_order_atomic` asserted
`SUM(legs) == orders.total`, but the client sent legs including the tip while `total`
excluded it. Web POS refused the sale at the counter; desktop wrote it locally, printed
the receipt, took the cash, and had the sync push rejected five times before parking it
as `failed`. Fixed by migration 66: reconcile against `total + tip_amount`. Desktop
`computeTotals` now returns `total` (the bill) and `amountDue` (bill + tip) separately.

**BUG-03/04 — desktop main process did not compile.** Three `TS2307`s. The documented
fix in `APPLY-desktop-build-fix.md` could not work: **TypeScript never applies `paths` to
a relative specifier** (proven with `--traceResolution`). Fixed by making
`shared/printing` a real package (`file:../../shared/printing`) with a project reference.
Also fixed the emitted `require` (was relative, resolved inside `dist/`) and packaging
(electron-builder ships `node_modules`, not `shared/`).

**BUG-05 — pos-login locked out duplicate emails.** `users` is `UNIQUE (business_id,
email)`, so the same email is _allowed_ in two tenants; a global `.ilike().single()` then
returned PGRST116 and the cashier was told "Invalid email or PIN" forever. Also `ilike`
is a pattern match and `_` is a legal email character, so `john_doe@x` matched
`johnXdoe@x`. Fixed: coarse `ilike` filter, exact case-insensitive match in JS, branch
disambiguation, 409 `AMBIGUOUS_ACCOUNT` instead of a lie about the PIN.

**BUG-09 — dine-in never deducted ingredients.** `/pay` had a four-line stock update:
no `track_stock`, no `sold_by='piece'`, no `stock_movements`, and no recipe, variant,
packaging or fuel deduction. Restaurants use `/pay`; restaurants have recipes. The
recipe system was bypassed on the one path built for it. 410 lines extracted to
`lib/stockEffects.ts`; both paths now call it.

**BUG-11 — shift close failed on a busy day.** PostgREST puts `.in()` filters in the
URL, 37 chars per UUID. At ~220 orders the request line exceeds the 8 KB proxy buffer.
`chunkIn` existed in `reports.ts` — used 9 times, but never in `shifts.ts`,
`reports-export.ts` or `dailySummary.ts`, **and its default chunk size was 500, which is
18.6 KB — over the limit it existed to stay under.** Moved to `lib/pgQuery.ts`, default
150, applied at all 22 sites. `fetchAllIds()` added because the `.select('id')` feeding
those lists could silently truncate at Supabase's row cap and report a phantom cash
surplus.

### P1 — shipped

- **BUG-06** `increment_loyalty_points` called with `p_delta`, defined `p_points`. See §5 — my analysis of this was wrong.
- **BUG-07** `/pay` "redeemed" points via `supabase.rpc('decrement')` — a lazy builder, never awaited, serialised into the update body, error not checked, and no such function exists. Customers redeemed points and kept them. Now uses `adjust_loyalty_points` (migration 67), deliberately _not_ `increment_loyalty_points` with a negative, because that one also does `visit_count + 1`.
- **BUG-10** `/pay` never wrote `tip_amount`.
- **BUG-12** Daily summary `qty` string-concatenated (`"02.001.00"`) — `numeric(12,2)` returns as a string. **Found by the compiler** once the row was typed.
- **BUG-13** `voidedCount` filtered a completed-only query for `'voided'`. Structurally always 0 since written.
- **BUG-14** ESC/POS subsystem was dead code, with a `print:preview` channel collision that would have crashed Electron at boot. Now `escpos:*`, wired, routed.

### Infrastructure

- **Schema drift gate** (`check-schema-drift.mjs`) — cast safety, function signature drift, duplicate declarations, index freshness.
- **`refresh-schema-index.mjs`** + migration 70 — one command, no dashboard copy-paste.
- **Version automation** — `npm run release:patch` bumps, builds, asserts, packages both installers.
- **Installer slimming** — `typescript` was a production dependency of `shared/printing`, so 34 MB including `tsc.exe` was being packaged into every till installer.

## 5. Failed attempts and things I got wrong

**Read this section first next time. It is the most useful part of this document.**

### Bugs I introduced

1. **Migration 66 broke every order.** I copied migration 65's INSERT, which passes
   `pump_id` as raw text into a `uuid` column. PostgreSQL has no assignment cast from
   text to uuid, so _every_ sale failed — not just tipped ones. It applied cleanly
   because **a plpgsql body is not type-checked at CREATE time**. Fixed by migration 69.
   Root cause: I tested against a fixture built from the migration files instead of the
   real schema. The user's schema dump caught it within minutes of being shared.

2. **`stage 5 --apply` deleted two files it should not have.** I read
   `PrinterSetupScreen.tsx` backwards — its docstring says it _replaces_ `PrintersTab`,
   and it calls `print:assign`/`print:unassign`, so it is the UI half of the new print
   subsystem, not superseded code. `SplitBillModal.tsx` owns _by-item_ split
   (`PATCH /api/orders/:id/split`), which `SplitPaymentPanel` does not do. Restored in
   `ac06e69`.

3. **`cleanup.sh` had three separate bugs I shipped:** stage gating declared but never
   used (all stages ran at once); `add_ignore()` not checking `ACTIVE` (stage leak);
   dirty-guard counting untracked files, which blocked the very stage meant to delete
   them. Combined with my telling the user `git stash push` without `-u`, this produced
   commit `f731ffd`, which committed the 20 files that were supposed to be deleted.

4. **The drift gate's own INSERT regex** had an optional `\(?` that ate a leading paren,
   unbalanced the depth counter, and made every INSERT silently skip as a "count
   mismatch" — so it reported **OK** on a migration that was broken. Exactly the failure
   mode it exists to prevent. Both the fix and the reason are commented in place.

### Analysis I got wrong

5. **BUG-06 blast radius.** I said every loyalty award silently fell back to the racy
   path. I read that off the repo's migration file. The **live database has `p_delta`**,
   and the code sent `p_delta` — so in production the atomic path was working. BUG-06
   only bit databases provisioned fresh from the repo. Worse, my "fix" would have broken
   a working path, which is why migration 68 exists. **Root cause of the drift:**
   `00_baseline.sql` and `swiftpos_consolidated_migration.sql` both declared the function
   with `p_delta` while `53_` declared `p_points`. The repo never agreed with itself, and
   `CREATE OR REPLACE` cannot rename a parameter, so every re-run failed silently.

6. **"`chunkIn` has never been called."** Wrong — 9 call sites. My grep for `chunkIn(`
   missed them all because every call is generic: `chunkIn<Row>(...)`.

7. **"`schema-index.json` has 16 tables."** Wrong — 92, with 6 missing. I read the number
   off my sandbox copy.

8. **Repeated path mistakes in command blocks:** `cd apps/server && ... && cd ..` lands
   in `apps/`, not the repo root — cost three rounds. Bash loops with `>/dev/null` on
   Git Bash emit `stdout is not a tty` and corrupt the exit code — reported 15 passing
   tests as failures, twice. Pasting YAML (`- run: ...`) as a shell command.

### The pattern

Every serious bug in this codebase — and both of mine — came through the same seam:
**two things that must agree, with nothing comparing them.** Client math vs server
guard. Migration file vs live database. Preload bridge vs IPC handler. Test fixture vs
real schema. The drift gate closes the database half of that. The others are still open
by inspection only.

## 8. Working notes for whoever picks this up

- **The user's environment is Git Bash on Windows.** `~` is `/c/Users/USER`. Paths with
  spaces must be quoted. `cd a/b && cd ..` does not return to the repo root. `>/dev/null`
  in loops emits `stdout is not a tty` and corrupts exit codes. **Give one command at a
  time, with absolute paths, and no clever loops.**

- **Deliver as a zip with the folder structure, not a patch.** Patch files caused
  repeated path failures; zips extracted over the repo worked first time. Always follow
  with `git status --short` and state the exact expected file count.

- **`git add -A` has burned this repo three times.** Mangled terminal pastes leave stray
  files behind and `-A` sweeps them in. Always name paths explicitly.

- **The repo's own gates are excellent and worth trusting** — 6 static checkers, a schema
  audit, an IPC parity check, 15 offline suites. Every bug found in this review lived in
  a _gap between_ them, never inside one.

- **Verify claims by running them.** In this session, "I checked and it's X" was wrong
  four times: the loyalty blast radius, the chunkIn call count, the index table count,
  and the PrinterSetupScreen supersession. Each took a round to unwind. `--traceResolution`,
  PGlite and a mock PostgREST all earned their keep.
